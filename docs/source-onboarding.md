# 信息源添加、自动识别与抓取预览

## 使用流程

在来源页选择“添加来源”，输入一个公开 HTTP(S) 网址。系统规范化网址、安全检查目标，识别
来源类型并使用临时配置抓取最多 10 条预览。检测和预览不会创建 `Source`、
`IntelligenceItem` 或 `CrawlRun`。

确认页显示实际识别类型、置信度、是否建议人工检查、检测说明，以及每条预览的标题、链接、
发布时间、简介和规则分类。用户只可填写名称、默认分类、启用状态和说明；采集器名称与配置来自
服务器端检测状态，页面不展示或提交原始 JSON。

保存来源不会自动更新。选择“保存并立即更新”时，系统先用短事务提交来源，再调用现有
`UpdatePipeline` 和进程内更新锁；更新失败不会回滚已经保存的来源。

## 自动识别范围

- RSS / Atom：先检查输入响应，再检查 HTML 的 `link rel="alternate"`，最后只尝试 `/feed`、
  `/rss`、`/atom.xml`、`/feed.xml` 四个路径；
- GitHub Releases：只接受明确的 `github.com/owner/repository` 或其 `/releases` 页面，规范化为
  Releases URL，并使用无需 Token 的 `GitHubReleaseCollector`；
- 普通 HTML 列表：只从固定常见列表选择器或稳定的同路径站内标题链接生成有限配置，不接收
  用户 CSS、XPath、脚本或代码；
- 无法可靠识别：明确标为“需要自定义采集器”，只允许保存为 disabled 待处理来源。

JavaScript 动态加载、登录、验证码、强反爬、结构特殊或没有稳定标题链接的网站不会被伪装成
识别成功。本阶段不使用 Playwright，也不绕过访问限制。

## SSRF 与响应边界

来源添加使用独立的安全 Fetcher：

- 只允许 HTTP 80 和 HTTPS 443，拒绝其他协议、非标准端口和 URL 用户名/密码；
- URL 最长 2048 字符；
- 拒绝 localhost、回环、私网、链路本地、未指定、保留和云元数据地址；
- 请求前解析 DNS，所有 A/AAAA 结果都必须是公网地址；
- 实际建连时再次解析并校验全部地址，随后直接连接选定的公网 IP；TLS SNI 和 Host 仍使用原始
  主机名，因此不会由 `httpx` 再次按主机名解析到不同目标；
- 最多跟随 4 次重定向，每一跳重新执行 URL、DNS 和 IP 校验；
- 允许经完整复查后的相对或跨主机重定向，拒绝 HTTPS 降级到 HTTP、重定向环、非标准端口和
  含 userinfo 的目标；底层自动重定向保持关闭；
- 检测与预览超时为 10 秒，单响应最多 2 MiB；
- 2 MiB 在流式解压后的字节上累计，缺少或伪造 `Content-Length` 不能绕过；连接、读取、写入和
  连接池等待均使用明确超时；
- 禁用 `trust_env`，不使用系统 HTTP(S) 代理；只转发固定无敏感含义的请求头白名单，不转发
  Authorization、Cookie、Host 或代理认证；
- 不读取本机文件，不接受项目路径，不执行页面脚本；
- 用户错误只显示净化说明，不显示解析 IP、本机路径、响应正文或堆栈。

检测一次最多执行 9 个发现请求（入口、最多 4 个 alternate、4 个固定常见 Feed 路径），随后
预览最多再执行 1 个请求；GitHub API 配额耗尽的 Atom 回退路径总计最多 2 个请求。自动生成的
HTML 配置固定为单页、最多 10 条预览，不会放宽 Collector 自身硬上限。

该 Fetcher 用于用户输入的检测和预览；用户添加来源的正式更新也通过同一安全 Fetcher 路由，
但仍由既有 CollectorRegistry、Collector 和 UpdatePipeline 执行。预置来源继续使用原有礼貌重试
Fetcher，`UpdatePipeline` 本身没有复制或改写。

## 临时检测状态

浏览器只持有随机 token。进程内 `DiscoveryTokenStore` 保存结构化 `DiscoveryResult` 和最多 10 条
预览，不保存完整 HTML；预览标题和简介也有长度边界。状态最多保存 15 分钟、最多 256 条；访问
时清理过期项，容量满时淘汰最旧项。保存/确认时先以锁原子占用 token，避免并发重复使用；失败
会释放仍有效的 token，提交成功后立即删除。伪造、缺失、过期或重复使用都必须重新检测。

该状态只存在于当前进程，不在多进程 worker 间共享；应用重启、切换 worker 或容量淘汰都会使
结果失效，页面会提示检测结果无效或已过期并要求重新检测。当前本地单进程启动方式与此一致。

## 来源详情、编辑与重新检测

详情页只允许编辑名称、enabled、默认分类和说明。入口 URL、collector 名称和配置不能直接编辑，
也没有来源删除入口。

“重新检测来源”会使用现有入口生成新的独立检测结果和预览，原配置此时不变。用户确认且新预览
可用后，短事务才替换系统检测得到的 URL、类型、collector 和配置；冲突或事务失败时旧配置保持
不变。不可用的重新检测只记录测试时间和检测状态，不覆盖当前 collector，也不删除历史资讯。

## 验收来源说明

Google Blog RSS、Qwen-Agent Releases 和普通 HTML 列表页仍只是技术验收来源，不代表正式、完整
或经过内容质量评审的来源库。本阶段不扩充正式来源库，也不优化来源内容质量。
